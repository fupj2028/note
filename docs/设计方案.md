| ② | 搜索页（全屏） | ①② 顶栏的搜索图标（**两边同一个入口**） | 一处输入，**两张表一起搜**，结果分两组：备忘录 N 条 / 摘录 N 条；命中词打底加粗；点结果跳到对应的编辑页或摘录详情 |

**摘录 tab**

| 编号 | 页面 | 从哪进 | 主要内容 |
|---|---|---|---|
| ⑩ | 摘录流 | 切到摘录 tab | 按天分节 + 每条带时分；**出处与时分贴在卡片最底部，时分靠右**；评论铺开前 2 条，多的收成「还有 N 条 ›」 |
| ⑪ | 单条摘录详情 | ⑩ 点某条 | 原文引用块 + 我的评论（逐条带时间）+ 底部追加评论。**长按正文只复制正文本身，长按某条评论复制那条评论**（按需复制）；**评论左滑露出删除按钮，点一下才删**（不再弹确认框） |
| ⑫ | 写摘录 | ⑩ 右下按钮 | 原文 / 出处 / 我的评论三块；模态页，不带底部栏。**在某个书名筛选下进来时，出处预填该书名**（可改）；在「全部」下为空 |

**跳转关系**

```
① 笔记列表（首页）
├─ 点「＋」        → ③ 编辑页（新建）
├─ 点某条笔记      → ③ 编辑页（打开）
├─ 长按某条笔记    → 直接复制整条到剪贴板（无面板）
├─ 点搜索图标      → ② 搜索页（跨两张表一起搜）
├─ 点顶栏标签图标 → ⑨ 分类管理
└─ 点顶栏「⋮」     → ⑥ 设置
                     ├─ 导出全部     → 写出文件 + 提示完整路径
                     ├─ 回收站       → ⑤ 回收站
                     └─ 分类管理     → ⑨ 分类管理

⑩ 摘录流
├─ 点「＋」        → ⑫ 写摘录（在当前书名筛选下会预填出处）
├─ 点某条摘录      → ⑪ 详情（原文 + 评论）
├─ 长按某条摘录    → 直接复制「原文 + 出处」到剪贴板
└─ 点搜索图标      → ② 搜索页（同上）

③ 编辑页「⋮」    → 分类 / 导出这条 / 置顶 / 移到回收站
⑪ 详情「⋮」      → 导出这条 / 移到回收站
⑤ / ⑨ / ⑫ 均为返回上一页
```

**还没做**：⑥ 里线稿画过的「正文字号」；导出目前只有纯文本（Markdown 未做）。

**三个硬要求落在哪**

| 要求 | 落点 |
|---|---|
| 复制粘贴体验好 | **① 列表项长按 = 直接复制整条**（一键进剪贴板，不再需要"长按→再点复制"两步）；**⑩ 摘录长按 = 直接复制原文**（有出处就连出处一起给）；③ 编辑页正文长按走系统文本选择；⑫ 原文输入框支持直接粘贴 |
| 导出 | 入口三个：⑥ 设置 →「导出全部」、③ 编辑页「⋮」、⑪ 摘录详情「⋮」。**写死到 `Download/备忘录/`**，导出完提示完整路径。格式见 §6 |
| 记录时间 | ⑩ 按天分节 + 每条带时分；⑫ 收录时间自动记为「现在」，存了不可改 |

## 2. 数据表结构

### 表 `note`（备忘录）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Long | 主键，自增 | |
| `title` | String | 非空，默认 `""` | 标题 |
| `content` | String | 非空，默认 `""` | 正文，纯文本 |
| `categoryId` | Long? | 外键 → `category.id`，`ON DELETE SET NULL`，可空 | 空 = 未分类 |
| `isPinned` | Boolean | 非空，默认 `false` | 置顶 |
| `deletedAt` | Long? | 可空 | 非空即在回收站 |
| `createdAt` | Long | 非空 | 创建时刻 |
| `updatedAt` | Long | 非空 | 修改时刻，列表排序用 |

索引：`updatedAt`、`categoryId`、`deletedAt`

### 表 `category`（分类）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Long | 主键，自增 | |
| `name` | String | 非空，唯一 | 不允许重名 |
| `isHidden` | Boolean | 非空，默认 `false` | 隐藏 = 不出现在 ① 的筛选栏 |
| `createdAt` | Long | 非空 | 决定显示顺序 |

### 表 `excerpt`（摘录）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Long | 主键，自增 | |
| `text` | String | 非空 | 书上的原文 |
| `source` | String | 非空，默认 `""` | 书名，独立字段 |
| `createdAt` | Long | 非空 | **收录时刻，写一次不再改** |
| `deletedAt` | Long? | 可空 | 非空即在回收站 |

索引：`createdAt`、`source`、`deletedAt`

### 表 `excerpt_comment`（我对摘录的评论）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | Long | 主键，自增 | |
| `excerptId` | Long | 外键 → `excerpt.id`，`ON DELETE CASCADE` | 删摘录时连评论一起清 |
| `text` | String | 非空 | 评论内容 |
| `createdAt` | Long | 非空 | 追加时刻 |

索引：`excerptId`

**只有你自己用，所以评论表里不存"谁写的"——没有作者字段、没有回复关系。**

### 「只追加」的落地

| 对象 | 能改吗 |
|---|---|
| 摘录原文 | **不能改**，只能删。保证摘录忠实于书上原句 |
| 摘录的收录时间 | **不能改**，写一次定终身 |
| 我的评论 | **只追加、不修改**；写错了删掉重发。多条评论可以挂在同一条摘录下，累积成跟帖 |

### 书名怎么管

书名是 `excerpt.source` 上的普通字符串，**不单独建表**。⑩ 顶部那排筛选 chip 来自 `SELECT DISTINCT source FROM excerpt`，出现过的书名自动进筛选栏，不需要"书的管理"页面。

### 标题规则（备忘录）

`title` 为空时保存自动取正文首行前 30 字；`title` 已有值就不再自动覆盖。

### 回收站规则（note 与 excerpt 共用）

- 删除 = 往 `deletedAt` 写当前时刻，不物理删除，所以能逐条恢复
- 每次打开 App 时扫一遍，`deletedAt` 超过 30 天的物理删除
- 不用 WorkManager、不用后台定时任务

### 为什么备忘录和摘录是两张表

浏览方式不一样（卡片库 vs 时间流），字段也不一样（标题/分类 vs 书名/评论），但**搜索是跨两张表一起做的**（见 §5），所以拆表不会带来"搜不到"的代价。

## 3. 分类行为规则

| 操作 | 行为 |
|---|---|
| 新建 | ⑨ 页面点「新建分类」，输入名字；重名直接拒绝并提示 |
| 重命名 | 只改名字，笔记归属不变 |
| 隐藏 | 从 ① 的筛选栏收起；笔记不受影响；在 ⑨ 页面可随时恢复显示 |
| 删除 | 该分类下所有笔记的 `categoryId` 置空（变成「未分类」），**笔记本体不删**；需二次确认，确认框里写明"该分类下 5 条笔记会变成未分类" |
| 隐藏时正在筛选 | 自动切回「全部」 |
| 排序 | 按 `createdAt`，第一版不支持拖动排序 |
| 「未分类」 | 不单独做筛选入口，未分类的笔记在「全部」里正常可见 |
| **归类入口** | **在 ③ 编辑页的「⋮」→「分类」**里选（列未分类 + 所有分类，隐藏的也列出来并标注）。原设计放在 ④ 长按面板，但 ④ 已改成"长按直接复制"，所以挪到编辑页 |
| 默认分类 | **不预建任何分类**，装完是空的 |

## 4. 外观设置

⑥ 设置页的「外观」分组两行：

| 设置 | 选项 | 默认 |
|---|---|---|
| 主题 | 跟随系统 / 浅色 / 深色 | 跟随系统 |
| 色系 | 跟随壁纸（动态取色）/ 紫 / 蓝 / 绿 / 橙 | 跟随壁纸 |

- 「跟随壁纸」用 Android 12+ 的动态取色（Material You），低版本自动退回紫
- 选具体色系时，从该种子色生成一套配色方案
- 两项都存在 DataStore 里，**下次打开还是你选的那个**
- ⚠️ 已知取舍：第一版自选色系只影响主色相关的几个角色（主按钮、悬浮按钮、选中态、筛选 chip 等），**不是完整的色调量级生成**。够看出区别，但不是逐档的 Material You 调色板

## 5. 搜索范围

一次输入，**两张表一起搜**，结果分两组显示。搜索在**独立的全屏搜索页**里，两个 tab 顶栏的搜索图标是同一个入口。

| 搜哪边 | 实际搜的字段 |
|---|---|
| 备忘录 | `title` + `content` |
| 摘录 | `text` + `source` + **评论的 `text`** |

评论进搜索是刻意的：你以后想找某条摘录，记得的往往是"我当时怎么想的"，而不是书上那句原话。

⚠️ **搜索是全局的**：搜索页里没有分类/书名的筛选栏，所以做不到"只在当前这个分类/这本书里搜"。要实现得给搜索页再加一层筛选条件，目前不做。

**匹配方式是纯子串**：连续几个字能命中（搜"制度"能带出"改变制度"），**跳字不行**（书里是"制度不是外部框架"，搜"制度框架"搜不到）。想要模糊匹配得上全文检索 + 中文分词，第一版不做。

用户输入里的 `%` 和 `_` 会做转义，否则搜"100%"会变成匹配一切。

## 6. 导出格式（给以后的**导入**留的契约）

> 动这套格式就必须同时改导入。完整的字段说明写在 `util/ExportFormat.kt` 的注释里。

**为什么不能是"拼一坨好看的文本"**：用户明确要求"导出功能可以给以后可能会有的导入功能留好兼容性"，所以导出必须是**能被机器解析**的格式 —— 分节 + `键: 值` 头 + 正文，并且带格式版本号。

**位置与命名**：固定写进 `Download/备忘录/`。

| 场景 | 文件名 |
|---|---|
| 导出全部 | `备忘录导出-yyyyMMdd-HHmm.txt` |
| 导出单条 | `标题（或出处）-yyyyMMdd-HHmm.txt`，文件名里 `/ \ : * ? " < > |` 和换行替换成空格 |

**结构示例**：

```
# 备忘录导出
# 格式版本: 1
# 导出时间: 2026-09-29T21:08:19+08:00

=== 分类
名称: 工作
隐藏: 否

=== 备忘录
标题: 银行卡号
分类: 工作
置顶: 是
创建: 2026-09-29T20:39:00+08:00
修改: 2026-09-29T20:41:00+08:00

正文原样写在这里

=== 摘录
出处: 示例书名
创建: 2026-09-29T20:51:00+08:00

这里放摘录的原文

--- 评论
创建: 2026-09-29T20:52:00+08:00

我的想法
```

**解析规则（导入按此实现）**：

1. 以 `=== ` 开头的整行＝新的一节，类型可选 分类 / 备忘录 / 摘录；`--- ` 开头＝当前节里的子节（评论）。
2. 节内**第一个空行之前**是 `键: 值` 头，空行之后到下一个标记之间是正文。
3. 头的值里，换行写成 `\n`、反斜杠写成 `\\`；导入时反向还原（标题是可以含换行的，不压成一行会把节拆坏）。
4. 正文里若出现以 `=== `、`--- ` 或 `\` 开头的整行，导出时前面补一个 `\`；导入时去掉一个。
5. **未知的节类型与未知的键一律忽略** —— 以后加字段时，旧版本的导入不该因此失败。
6. 时间一律是**带时区偏移的 ISO-8601**，换时区后时间不会漂移。

**单条导出的文件用的是同一个文件头 + 一个节**，所以同一个导入既能吃"全部"也能吃"单条"。

**已验证**：2026-09-29 两种导出各跑一次，把文件从真机拉回来逐行核对过结构、时区与空行保留。

## 9. 权限

**不申请任何危险权限。** 导出走 MediaStore 写自己的 Downloads 条目（API 29+ 免权限），位置由程序定死，因此不需要存储权限——**这条替掉了最早"走 SAF 让用户挑位置"的方案**：用户要求导出到固定文件夹，MediaStore 更省事且同样零权限。安装时不会出现权限弹窗，以后万一要上架也不用解释权限用途。

`allowBackup=false`：数据只存这台手机，不走系统云备份。
